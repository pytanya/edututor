# Медиа материалов: генерация графиков и картинок к урокам — архплан (Этап 6)

Дата: 2026-09-08. Воркспейс: `C:\otus\edututor`. Тип: новое под-системное
изменение бэкенда + фронтенда. Статус: **ПРОЕКТ (архитектурный план), код не
меняется**. Коммиты не выполняются без явной просьбы.

## 1. Проблема и место в продукте

Сегодня весь контент уроков текстовый: `theory`/`practice`/`quiz` отдаются
типизированными конвертами с markdown + LaTeX, фронтенд рендерит их единым
пайплайном `<Latex>` (`frontend/src/components/Latex.jsx`,
`frontend/src/utils/markdown.js`). Картинок и графиков нет нигде: нет инструмента
агента, нет image-токена в markdown-парсере, нет статики/медиа-эндпоинта на
бэкенде, `ContentEnvelope` содержит только `type/text/payload/difficulty`
(`adaptive_tutor/src/models/schemas.py:63-70`).

Запрос (живой smoke, 2026-09-08): ученик спрашивает «дай картинку к задаче»
(пример — тема «круговые диаграммы»), а планировщик ошибочно вызывает
`generate_quiz` — единственный «инструмент, похожий на задание». Причины:
нет подходящего инструмента, в системном промпте нет правил про картинки, а
контур не умеет доставлять изображения. Это не только UX-дыра: для
статистики/математики dual-coding (текст + рисунок) — базовая педагогическая
техника, а граф знаний/диаграммы числятся «второстепенным» пунктом gap-аудита
(`docs/superpowers/2026-09-04-gap-audit-edututor-vs-reference.md`, §4.4,
таблица C).

**Цель этапа:** научить репетитора сопровождать теорию/задачи/вопросы точными
графиками (круговая, столбцы, линейный) и, опционально, иллюстрациями; картинка
должна корректно жить в чате, в Knowledge Wiki и в OKF-экспорте.

## 2. Дайджест исследования (факты, проверено 2026-09-08)

### 2.1 Семейство Qwen — три РАЗНЫЕ способности, их нельзя смешивать

| Линейка | Тип | Что даёт | Годится для точных графиков? |
|---|---|---|---|
| Qwen-Image 2.0/3.0 (Alibaba) | Diffusion image-gen | иллюстрации, постеры, инфографика «под ключ», редактирование | ❌ может «галлюцинировать» долями/подписями |
| Qwen 2.5/3.x text + code-interpreter (matplotlib/plotly) | LLM + код | «модель считает и рисует кодом» | ⚠️ точно, но нужен безопасный код-сандбокс и тяжёлые зависимости |
| Qwen2.5-VL / Qwen3.x-Max (vision) | Мультимодальный **вход** | понимает/извлекает данные из чужих графиков, скриншотов, grounding | вход-понимание, не выход-генерация |

Вывод для продукта: для **педагогически точных** диаграмм (доли, оси, подписи)
диффузионная генерация изображений не подходит в принципе. Ей место — только
иллюстративный трек (см. §4.3).

### 2.2 Провайдер RU (RouterAI), на котором реально работает продукт

Продукт ходит в RouterAI через OpenAI-совместимый API (`src/llm/router_ai.py`,
base URL `https://routerai.ru/api/v1`). Факты из доков RouterAI (2026-09-08):

- Существует **выделенный эндпоинт генерации изображений**
  `POST /api/v1/images`: запрос `{model, prompt, n, aspect_ratio, size, quality,
  output_format, seed, ...}`, синхронный ответ — изображения **base64** в
  `data[].b64_json` + `usage.cost` в рублях. Не chat/completions.
- Модели с `image` в `output_modalities`: `openai/gpt-image-1`,
  `black-forest-labs/flux.2-pro`, `bytedance-seed/seedream-4.5`,
  `microsoft/mai-image-2.6(-flash)`, диалоговые `google/gemini-*-flash-image`
  (через chat/completions с `modalities`). Каталог фильтруется по
  `GET /api/v1/models`.
- Стоимость возвращается в `usage.cost` (₽) — встраивается в существующий
  учёт бюджета (как `RouterAITokenCounter`, RUB→USD).
- Qwen-Image на RouterAI **не подтверждена** в каталоге → модель для
  иллюстративного трека делать конфигурируемой строкой, а не хардкодом.

GLOBAL-контур (OpenRouter) также имеет image-output модели, но RU — основной
(текущий `TUTOR_REGION=RU`), поэтому трек проектируется под `/images` RouterAI с
абстракцией клиента (аналогично `src/llm/`).

### 2.3 Внутри репозитория: точки интеграции (проверено)

- Единый рендер всего текста: `Latex.jsx` + `utils/markdown.js` (токены
  `text|math|code|strong|link`, блоки `paragraph|heading|list|quote`). **Нет**
  image-токена, нет `react-markdown`, нет svg/mermaid. Один новый токен =
  картинки во всех поверхностях: блоки чата и `TopicArticle` wiki
  (`TopicArticle.jsx:58` рендерит `article.body` тем же `<Latex>`).
- SSE `message` = `{content, envelope, adaptive, error, session_id}`; конверт
  санитится (`sanitize_envelope`, `src/agent/envelope.py:168-174`: вырезает
  только payload-ключи с префиксом `_` и `correct_answer`) — любые
  **не-секретные** ключи payload проходят до фронтенда. Топ-уровневые ключи
  конверта Pydantic отбрасывает (`extra="ignore"`).
- Инструменты агента: `TOOL_SCHEMAS` (`src/agent/tools.py:142`) + диспетчер
  `_call_tool`; LLM-внутренний инструмент `generate_quiz` — образец отдельного
  короткого вызова с учётом бюджета. Результаты инструментов идут в
  `state.tools_result` (не в историю сообщений) + наблюдение модели
  (`_observation_text`, `src/agent/loop.py:575`).
- Wiki: markdown-файлы `data/knowledge_wiki/<sid>/<subject>/<topic>.md`,
  обогащение тела `enrich_body` (`src/wiki/enrich.py:30-61`) ролью `fast`;
  формат тела — markdown. OKF-бандл: `emit_okf_bundle` (`src/export/okf.py:34`)
  пишет `*.md`; валидатор ходит только по `*.md` — media-файлы не мешают.
- Статики/медиа на бэкенде **нет** (нет `StaticFiles`/`FileResponse`/mount);
  Vite-прокси проксирует `/chat /student /knowledge /health /api`
  (`frontend/vite.config.js:7-15`).
- Зависимости: `matplotlib`/`plotly`/`pillow`/`cairosvg` **отсутствуют**
  (`pyproject.toml`). Зато уже есть: `httpx` (для `/images`), `pytest`+`ruff`
  (бэкенд), `vitest`+RTL+oxlint (фронтенд).

## 3. Ключевые решения (требуют подтверждения — см. §10)

Рекомендуемая архитектура — **два трека** + **одна универсальная доставка**.

- **R1. Точные графики = детерминированный серверный рендер SVG** (НЕ
  diffusion, НЕ matplotlib). Модель не рисует пиксели: новый инструмент агента
  `make_figure` принимает **структурированные данные** (`kind`, подписи,
  значения) и возвращает готовый SVG, вычисленный кодом. Доли/координаты точны
  на 100 %, промпт не может «дорисовать» лишний сектор; поведение
  юнит-тестируемо; стоимости LLM нет.
- **R2 (флаг, отложено): иллюстрации — отдельный инструмент** `make_illustration`
  через `POST /api/v1/images` RouterAI (модель — конфигурируемая строка).
  Используется только там, где точность не нужна (сюжетные картинки, схемы для
  visual-стиля). Выключен по умолчанию: стоит денег, недетерминирован.
- **R3. Доставка — markdown-image токен `![подпись](src)`**, добавленный в
  `utils/markdown.js` + ветку рендера `<img>` в `Latex.jsx`. Один механизм
  работает в чате (все блоки), в wiki-статьях и при экспорте. Картинку в текст
  конверта вставляет **сервер** после финализации (модель картинки сама не
  пишет — это исключает галлюцинации URL/дата-URI и раздувание контекста).
- **R4. SVG-графики по умолчанию — inline `data:image/svg+xml;base64,…`**
  (размер 1–8 КБ): история, wiki и OKF остаются самодостаточными, бэкенд не
  обзаводится static-эндпоинтом. PNG-иллюстрации (R2) крупные → **файл + новый
  эндпоинт `GET /media/{file}`** + запись `/media` в vite-прокси.
- **R5. Защита**: `src` изображений разрешается только на `data:image/…;base64`
  и same-origin `/media/…` (белый список схем); SVG генерится нашим кодом с XML-
  экранированием всех строк; лимиты сложности фигуры; R2 — только при
  включённом флаге и в рамках существующего бюджета сессии.

### 4.2 `make_figure` — контракт инструмента (R1)

Схема (OpenAI-совместимая, добавляется в `TOOL_SCHEMAS`):

```jsonc
{
  "name": "make_figure",
  "description": "Построить ТОЧНЫЙ график/диаграмму по данным (SVG, серверный рендер). "
                 "Используй для наглядности в theory/practice/quiz: доли, сравнения, ряды. "
                 "НЕ рисуй картинки текстом и НЕ вставляй изображения в текст сам — "
                 "система прикрепит рисунок к твоему ответу автоматически.",
  "parameters": {
    "type": "object",
    "properties": {
      "kind": {"type": "string", "enum": ["pie", "bar", "line"]},
      "title": {"type": "string", "description": "Заголовок (короткий, до 120 символов)"},
      "data": {
        "type": "array",
        "items": {"type": "object",
          "properties": {
            "label": {"type": "string", "description": "Подпись (до 60 символов)"},
            "value": {"type": "number", "description": "Числовое значение (>=0)"}},
          "required": ["label", "value"]}
      },
      "caption": {"type": "string", "description": "Подпись рисунка (alt-текст)"},
      "show_values": {"type": "boolean", "default": true}
    },
    "required": ["kind", "data"]
  }
}
```

Ограничения рендера (`figures.py`):
- `kind=pie`: значения нормализуются к сумме 100 %; сектора вычисляются кодом
  (точные градусы); если сумма 0 — отказ с сообщением модели.
- `kind=bar`: не более 12 категорий; ось Y автоподбирает «круглую» шкалу.
- `kind=line`: один/несколько рядов `{label: [{x, y}]}`; не более 40 точек/ряд.
- Любые строки (label/title/caption) XML-экранируются; SVG без скриптов/внешних
  ссылок — только фигуры, текст, оси, легенда.
- Итог — компактный SVG (viewport ~640×360/480), шрифт системный (рендер на
  клиенте), цвета из фиксированной палитры CSS-переменных фронтенда.

Результат инструмента (идёт в `state.tools_result`, а модели — только короткое
наблюдение, см. §4.4):
`{"status":"ok","data":{"kind":...,"caption":...,"mime":"image/svg+xml","b64": "<base64 svg>"}}`.

### 4.3 `make_illustration` — контракт инструмента (R2, за флагом `illustrations_enabled`)

Схема: `{prompt: string, aspect_ratio?: "1:1"|"16:9"|"9:16", caption?: string}`.

Исполнение: `src/media/client.py` → `POST https://routerai.ru/api/v1/images`
(model из `settings.media_illustration_model`, `output_format=png`, `size=1K`).
Результат — PNG (base64) сохраняется в `data/media/<sha256>.png` через
`src/media/store.py`; инструмент возвращает URL `/media/<sha256>.png` (в
наблюдении модели) и файл — в `state.tools_result`. Стоимость (`usage.cost`, ₽)
переводится в USD как в `RouterAITokenCounter` и списывается в бюджет сессии;
при превышении бюджета/сбое сети — fail-soft: картинка заменяется текстовым
замечанием, чат не падает (паттерн generate_quiz, `tools.py:_generate_quiz`).

`store.py`: атомарная запись `tmp`+`replace`, GC по (max_age_days, max_total_mb),
имена контент-адресные (sha256) — дедуп и безопасные URL.

### 4.4 Сервер: прикрепление рисунка к ответу (R3/R4)

Место: `src/api/server.py`, в `_run_chat`, после того как агент вернул
`AgentGraphState`, до `sanitize_envelope`/записи истории (анатомия — как уже
сделано для quiz-карточки `generate_quiz` в `server.py`):

1. Читаем `result.tools_result` за этот ход (для каждого финального конверта,
   который будет опубликован как `message`).
2. Если в ходу успешно отработал `make_figure` (и есть финальный конверт
   `theory`/`practice`/`quiz` — картинка к самому первому блоку хода):
   - из b64 собираем `data:image/svg+xml;base64,…`;
   - **дописываем** в конец `envelope.text` перевод строки + `![<caption>](<data-uri>)`;
   - записываем событие наблюдаемости `media.figure` (модель, kind, размер, cost=0).
3. `make_illustration` (R2): в конец текста дописывается
   `![<caption>](/media/<sha>.png)` (URL, не inline).
4. Важно: **модели в следующих ходах история отдаётся без картинок** — при
   сборке LLM-контекста (`session_store.to_llm_context`/`build_messages`) из
   текстов сообщений вырезаются markdown-image токены (регэксп `!\[[^\]]*\]\([^)]*\)`).
   Это защищает контекст от дата-URI и от эха-галлюцинаций модели.

Quiz-ветки не ломаются: `_guard_quiz_envelopes` смотрит только
`text/payload.answer_type|options|_correct_answer`; секрет квиза остаётся в
`session.last_quiz` отдельно. Один `make_figure` на ход (кап) — чтобы не
раздувать сообщение.

### 4.5 Фронтенд: image-токен в едином рендерере

- `frontend/src/utils/markdown.js`: в `parseBlocks`/`parseInline` — распознавание
  `![alt](src)` на отдельной строке как блока `image {alt, src}`.
- `frontend/src/components/Latex.jsx`: ветка рендера
  `<figure><img src={safeSrc} alt={alt}/><figcaption>{alt}</figcaption></figure>`.
- `frontend/src/utils/safeSrc.js` (новый): разрешает только
  `data:image/svg+xml;base64,`, `data:image/png;base64,`,
  `data:image/jpeg;base64,` и относительные `/media/…`; всё остальное — `null`
  (не рендерим). XSS-вектор закрыт.
- `InlineText` (квиз-опции) не трогаем — картинки только в теле блока.
- Vite-прокси: добавить `/media`.

Никаких новых блоков/типов конверта: `type` конверта не меняется, всё едет
внутри `envelope.text`. Значит **схема `ContentEnvelope` и промпты конвертов не
меняются**, фронтенд-диспетчер (`Chat.jsx` `AgentMessage`) не трогается.

### 4.6 Промпты

`src/agent/prompts.py`, `SYSTEM_PROMPT` — добавить правило:

```
- Для наглядности (диаграммы, доли, сравнения) можно вызвать инструмент
  make_figure и передать ему ЧИСЛОВЫЕ данные. Картинку в финальный текст
  НЕ вставляй и НЕ описывай картинкой — система сама прикрепит рисунок к твоему
  ответу. Не злоупотребляй: не более одной фигуры на ответ.
- У тебя НЕТ возможности нарисовать изображение текстом/в JSON.
```

(Одновременно это закрывает исходный дефект «дай картинку → generate_quiz»:
у модели появляется релевантный инструмент, а при его неприменимости —
предписание отвечать текстом, а не звать generate_quiz.)

### 4.7 Wiki и OKF-экспорт

- **Wiki**: инструмент `make_figure` доступен и в основном диалоге; для тела
  статьи рисунок попадает естественно: текст теории с уже встроенной
  `![…](data:image/svg+xml;base64,…)` сохраняется в тело статьи
  (`store.upsert`/`apply_record`), потому что статья строится из блоков
  конвертов того же текста. SVG-inline самодостаточен — файловая статья не
  требует соседних ассетов.
- **OKF**: `topics/*.md` пишутся из тех же данных; inline-SVG не требует шага
  копирования. PNG-иллюстрации R2 (URL `/media/…`) на этапе экспорта
  копируются в `out_dir/assets/` и src переписывается на относительный путь —
  это отдельная подзадача R2 (см. §7), вне MVP.

## 5. Потоки (sequence, словами)

**Ход «объясни круговые диаграммы» (целевой):**

1. `planner` решает, что нужен пример: вызывает `make_figure{kind:"pie", title,
   data:[{label:"Математика", value:25}, …], caption:"Пример диаграммы"}`.
2. `tools` исполняет `make_figure` детерминированно (миллисекунды, без LLM);
   в `state.tools_result` — SVG b64; модели уходит только строка «Рисунок
   подготовлен (kind=pie, 2.1 КБ)».
3. `planner` финализирует `theory`-конверт текстом + формулами.
4. `finalize` → сервер дописывает `![…](data:image/svg+xml;base64,…)` в конец
   текста; санитизация; история; SSE `message` (одним сообщением-блоком).
5. Фронтенд `<Latex>` разбирает блок `image` и показывает `<figure>`.
6. Следующие ходы: текст для модели идёт без image-токена.

## 6. Безопасность и надёжность

- `src` изображений: только `data:image/svg+xml|png|jpeg;base64` и same-origin
  `/media/` (функция `safeSrc`, юнит-тесты). Внешние URL не рендерятся
  (нет SSRF/трекинга через `<img>`).
- SVG генерится нашим кодом; весь текст XML-экранируется; запрещены
  `<script>`, `on*`, `href`/`xlink:href` к чему-либо кроме чистой геометрии;
  тест-кейсы с инъекцией (`<script>`, `&`, `"`, `]]>`).
- Лимиты: значения/категории/точки/символы (§4.2), `figures_max_kb`.
- R2: кап стоимости `media_illustration_max_usd` + общий `BudgetGuard` сессии;
  таймаут запроса (как `llm_timeout_sec`); fail-soft — при ошибке текстовое
  примечание, не падение хода.
- Секреты: картинки в `envelope.payload` не появляются (картинка в `text`);
  scrub/санитизация логов не затрагиваются.

## 7. Майлстоуны (приблизительные объёмы)

- **M1 (MVP, R1): точные SVG-графики в чате.** `src/media/figures.py` (pie/bar/
  line) + инструмент `make_figure` + серверное прикрепление + image-токен и
  `<img>` во фронте + промпт-правило + конфиг-флаги. Бэкенд: `test_media.py`
  (рендеры: сумма 100 %, инъекции, лимиты), `test_api.py` (SSE-сообщение
  содержит `![…](data:image…)`; картинка не уходит в следующий контекст LLM).
  Фронтенд: `markdown.test.js`, `blocks.test.jsx` (рендер image; safeSrc-фильтр).
  Зависимости: НЕТ новых (SVG из stdlib). Объём ≈ 6–8 рабочих файлов.
- **M2: wiki/экспорт.** Проверка/фиксы: картинки из M1 в статьях и OKF
  (скорее всего бесплатно за счёт inline-SVG); тесты.
- **M3 (R2, по желанию): иллюстрации.** `src/media/client.py` + `/api/v1/images`
  + `store.py` + `GET /media/{file}` + vite-прокси `/media` + `make_illustration`
  (флаг off) + шаг копирования ассетов в OKF. Зависимость: только httpx (уже
  есть). Объём ≈ 5–7 файлов. Стоимость: деньги за вызовы — поэтому за флагом.
- **M4: доработка «галлюцинации» generate_quiz** — покрывается правилом из
  §4.6; отдельный регресс-тест на запрос «дай картинку» (модель НЕ должна
  звать generate_quiz; с включённым make_figure — вызывает его или отвечает
  текстом). Тест на фейк-LLM в `test_api.py`.

Порядок не жёсткий; M2 фактически сливается с M1.

## 8. Критерии приёмки (наблюдаемые)

- Демо: теория про круговые диаграммы с примером-диаграммой в чате; квиз по
  «чтению диаграммы» с картинкой в вопросе.
- Картинка присутствует в истории сессии и при восстановлении ленты; отсутствует
  в LLM-контексте следующих ходов.
- Backend: `pytest` (новые: рендеры, лимиты, инъекции, SSE, отсутствие image в
  контексте) зелёные; `ruff` чист. Frontend: `vitest` + `lint` чисты.
- Отсутствие секретов/внешних URL в `src` картинок (автотесты).
- R2: при выключенном флаге инструмента нет в схемах; при включённом — fail-soft
  при сбое.

## 9. Что НЕ входит (границы)

- Интерактивные графики (клик/зум) — только статичные изображения.
- «Извлечь данные из картинки» (Qwen2.5-VL/OCR) — отдельная фича.
- Математические построения геометрии (углы, окружности по построению) —
  отдельная фича поверх M1 (kind расширяемый).
- Генерация видео/анимаций.
- Редактирование (image-to-image) сгенерированных картинок.

## 10. Открытые вопросы (подтвердить до имплементации)

1. Подтвердить **R1-подход** (детерминированный SVG, не matplotlib-код и не
   diffusion) как основной для «материалов».
2. Нужен ли **R2-трек иллюстраций** в этом этапе или отложить (рекомендация:

4. Куда картинка липнет при нескольких блоках в одном ходе — к первому

   static-эндпоинт и в M1).
