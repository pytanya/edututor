# Конспекты: переработка панели, целостность предмета, читаемость — дизайн

> Статус: утверждено к планированию (макеты согласованы в браузере 2026-09-18). Реализация не выполнялась.
> Причина: жалобы UX — «нет конспектов по текущему предмету (истории), всё враздрос, материал не прочитать карточкой».
> Референс: `C:\otus\project_work` (KnowledgeWikiPanel, TopicModal, NoteItem — карточки, прогресс-бары, типизированные заметки).
> Зависимости: E4 wiki (`src/wiki/*`), панель `KnowledgeWikiPanel.jsx`/`TopicArticle.jsx`.

## 1. Цель и границы

- **Читаемость**: тело конспекта реально доступно — автообогащение работает (сейчас фактически нет), ридер показывает заметки карточками с цветом по типу.
- **Целостность предмета**: конспекты по предмету сессии видны именно под этим предметом; дубли/«общая тема» сливаются; дисциплина под разными именами канонизируется.
- **Навигация**: активный предмет сессии раскрыт первым, чипы-фильтры по предметам, карточки с прогресс-баром и датой, статистика.

**Вне границ:** LinUCB (Этап 5), ФГОС-сверка, полноэкранный раздел конспектов (остаёмся в панели сайдбара), смена модели обогащения (тот же fast-LLM).

## 2. Диагноз (корни проблем)

1. **«Не вижу конспектов по истории»**:
   - панель грузит все предметы сразу (`api.wiki(studentId)` без `?subject=`), текущий предмет не подсвечивается;
   - предмет не доезжает до записи в evaluation-ветке: `server.py:1922` использует `body.subject` **без** fallback на `session.subject` (в review-ветке `:1313` fallback уже есть) → статьи падают в «общая тема»;
   - реальные данные: `stu_8b16adb3` — тема «Синтаксис…» лежит и в `русский-язык`, и в `общая-тема` (мастерство раздвоено).
2. **«Враздрос»**: одна дисциплина под разными именами (папки `вероятность-и-статистика` и `вероятность-и-математическая-статистика`); тепловая карта MasteryWall — плоская, без группировки (по макету убрана).
3. **«Материал не прочитать»**: `_schedule_enrich` (`server.py:577`) запускается только при **пустом** теле, а тело-заглушка непустое → автообогащение не срабатывает никогда; кнопка «Обогатить» в ридере показывается только при `body.trim() <= 20` (`TopicArticle.jsx:14`), заглушка длиннее → кнопки нет. Итог: пользователь видит только заглушку «Материал накапливается…».

## 3. Данные: целостность предмета (backend)

### 3.1 Канонизация при записи

В `src/wiki/store.py`:

- `canonicalize(subject: str) -> str`: trim, схлопывание пробелов, срез точки на конце, регистро-независимый поиск в алиас-мапе → канон; иначе исходный trimmed.
- Алиас-мапа `settings.subject_aliases: dict[str, str]` (`config.py`, `{вариант: канон}`), например:
  `{"общая тема": "", "вероятность и математическая статистика": "вероятность и статистика"}`. Пустое значение канона = «предмет не задан».
- В `apply_record` и `sync_mastery`: `subject = canonicalize(subject or r.get("subject") or "")`. Если после канонизации пусто — `_infer_subject(topic)`:
  - ищем существующую статью с таким `slug(topic)` в любом предмете → возвращаем её subject;
  - иначе `"общая тема"`.
- Функция `_infer_subject` — чистая, переиспользуется миграцией.

### 3.2 Доставка subject до записи

- `server.py:1922` (evaluation): `subject=body.subject or session.subject` (как уже в review-ветке).
- При старте из графа `App.jsx` уже несёт `meta.subject` — проверить, что доходит до `runTurn` (исправить при необходимости).

### 3.3 Миграция существующих данных

Новый модуль `adaptive_tutor/src/tools/wiki_normalize.py`, запуск `python -m adaptive_tutor.tools.wiki_normalize` (идемпотентно):

- пройти все `<base>/<student_id>/<subject>/<topic>.md`;
- канонизировать subject; при изменении предмета — переместить файл в новый каталог;
- **merge-дедуп** по ключу `(canonical subject, topic)`:
  - `attempts += attempts`, `correct += correct`, `mastery = max(mastery_a, mastery_b)` (консервативно), `accuracy = correct/attempts` (0 при 0 попыток), `last_studied = max`, `grade/curriculum` — из более заполненной;
  - заметки объединяются с дедупом по `feedback[:180]`, кап `MAX_NOTES=10`;
  - слабые места/концепции — объединение с дедупом;
- удалить пустые каталоги (в т.ч. пустую «общая-тема»), пересоздать `_index.md`.

Отчёт: сколько статей перемещено/слито/осталось «общая тема» без кандидата.

В `TopicArticle`:

## 5. Панель «Конспекты» (frontend `KnowledgeWikiPanel`)

1. **Stats-бар** (из отфильтрованных данных): тем / попыток / ср. мастерство / точность.
2. **Чипы-фильтры**: `Все · N`, далее по одному на предмет с количеством. Активный — предмет текущей сессии (`subject` из props) по умолчанию; клик по чипу — показать только этот предмет (клиентская фильтрация уже есть, расширяем на уровень групп).
3. **Группы предметов**: активный предмет — первой и раскрытой, остальные свёрнуты (состояние `collapsedSubjects` уже есть). Сортировка групп: активный предмет, затем по алфавиту.
4. **Карточки статей** вместо строк: цветная точка-индикатор (high/mid/low), название с `Latex`, прогресс-бар mastery с заливкой, `NN%`, «попыток: N · дата», кнопка `✕`. Сортировка внутри группы: `last_studied` по убыванию (свежие сверху).
5. **Поиск**: ищет по теме/названию/предмету + **концепциям** (как в референсе).
6. Удаление/открытие — как сейчас (`api.deleteWiki`, `api.wikiArticle`), открытие — в ридер `TopicArticle`.

## 9. Крайние случаи

- «Общая тема» без кандидата (нет похожей статьи с предметом) → остаётся группой, но с нейтральным заголовком «Общая тема»; при последующем ответе с предметом — канонизация разрулит.
- Дубли в двух **разных** реальных предметах (одинаковый topic) — не сливаются (легитимно: напр. «Системы уравнений» в алгебре и физике).
- Миграция с битым файлом → пропустить, не ронять (как `get` сейчас).
- Канонизация не должна менять человекочитаемые имена: только регистр/пробелы/известные алиасы.
- Обогащение: один вызов на статью, пока тело — заглушка; ошибки LLM — fail-soft, заглушка остаётся.
- Пустая база → текущее пустое состояние («Пройдите квиз…»).

## 10. Тесты

Backend:
- `canonicalize`: алиас, регистр, двойные пробелы, точка, пустая строка → «»; `_infer_subject` по существующей статье; fallback «общая тема».
- `apply_record` с пустым subject: повторный ответ по существующей теме подхватывает предмет; новый topic без предмета → «общая тема».
- Миграция: старая структура (дубли «общая-тема» + реальный предмет, разные имена дисциплины) → слито/перемещено/индекс пересоздан; идемпотентность повторного прогона.
- `_schedule_enrich`: тело-заглушка → запуск обогащения; пустое → запуск; заполненное → нет.
- API-регрессия: `/wiki` по-прежнему группирует по предметам.

Frontend (vitest):
- Панель: активный предмет первой группой и раскрытой; чип-фильтр показывает один предмет; карточка рендерит прогресс-бар/дату; сортировка по `last_studied`; поиск по концепциям.
- Ридер: кнопка «Обогатить» видна при теле-заглушке; типизация заметок (error/clarification/info); навигация пред./след.
- Прогон: `ruff`, `pytest`, `eslint`, `vitest`.
